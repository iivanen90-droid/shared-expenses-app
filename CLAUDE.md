# Порядок роботи над Tricount

Загальні правила проєкту та команди перевірок містяться в [AGENTS.md](AGENTS.md).

## Гілки та pull request

- `develop` — основна (default) гілка GitHub.
- `develop` — захищена гілка для інтеграції змін під час розробки.
- Кожна задача виконується в окремій гілці від актуального `origin/develop`.
  Для гілок агента використовуй префікс `codex/`.
- Зміни подаються через pull request із базовою гілкою `develop`.
  Перед створенням PR перевір, що base — `develop`.
- Прямі push у `develop` заборонені. Force push і видалення `develop` заборонені.
  Правила діють і для адміністраторів; обходити або послаблювати захист не можна.
- Перед злиттям Антон переглядає зміни. Потрібне щонайменше одне схвалення
  (required approvals = 1); автор PR не схвалює власний PR.
- Нові коміти скасовують попереднє схвалення: перед злиттям потрібен повторний review.
- Перевірка Codex є додатковою; вона не замінює схвалення Антона.
  Поки його GitHub-логін не погоджено, не вигадуй reviewer і не додавай CODEOWNERS.
- Не роби прямий push у `main`. Окремі зміни до `main` потребують погодженого PR.

Приклад початку задачі в чистій робочій директорії:

```sh
git fetch origin
git switch -c codex/task-name origin/develop
```

Збережи наявні незакомічені зміни перед зміною контексту. За потреби використовуй
окремий worktree; не скидай і не перезаписуй зміни користувача.
Перед PR виконай перевірки з `AGENTS.md` та опиши результат і неперевірені частини.
Якщо тариф чи права GitHub не дозволяють застосувати захист, повідом користувача
та узгодь рішення з Антоном; не позначай налаштування завершеним і не послаблюй вимоги.
